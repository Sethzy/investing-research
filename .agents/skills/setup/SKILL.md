# Install and interview

Use this workflow when the user supplies this repository and says install, set up, or onboard. Read `docs/setup.md` and `AGENTS.md`. Complete all steps you can; ask only for missing user-specific information. Never use another person's local files, portfolio or browser session.

1. Clone the user's supplied Git URL to an appropriate new directory if needed. Inspect the installer. Check `git`, `uv`, and Node 22+. Install missing prerequisites with an existing trusted package manager when authorized; otherwise explain the exact prerequisite. Run `bash scripts/install.sh --no-interview`. Do not launch an interactive prompt on a noninteractive tool and wait indefinitely.
2. Use Codex automatically; never ask the user to choose an agent host. Interview conversationally in small batches: timezone, base currency, investing horizon/style, markets and exchange-qualified watchlist, preferred daily time or on-demand only. Ask separately whether they want portfolio sizing; if yes, obtain actual holdings and explicit risk limits. Do not turn an unanswered risk question into a default allocation. Preferences and limits must be the user's own answers.
3. Use `uv run invest setup --help`. The terminal wizard is the canonical schema and validation path. For a conversational interview, assemble its `--answers` JSON contract in an ignored file and apply it through the command (see `docs/setup.md`); do not bypass validation by inventing keys. Preserve existing companies and answers; revisit saved preferences only when requested. Never echo sensitive holdings in logs.
4. Ask the user to sign in to X in their own browser and identify the profile. Never ask for passwords, cookies, tokens or copied profiles. Explain a local OS cookie/Keychain access prompt when applicable. Run `doctor --live-x`; a real successful response is required to call X working. If authentication fails, guide them through `docs/x-auth.md`; retry only after a relevant change. If unavailable, continue independent installation/research and explicitly mark X pending. Do not disguise a browser fallback as a successful Bird check.
5. Resolve each requested watchlist item against official public sources: exchange, legal name, trading/reporting currencies, assets and official reporting links. Ask about genuinely ambiguous tickers. Build a Company JSON following `examples/company-mlx.json` in `private/`, then run `watch-add`. Raw watchlist wishes are not confirmed company identities.
6. Run the synthetic model example and doctor. Check `soffice` availability: LibreOffice is needed to synchronize validated Excel results into Markdown. If absent, explain the unverified working-workbook status and guide installation; never claim a model report was published. Follow `docs/excel-models.md` for the Markdown-first, linked-Excel workflow. Explain that synthetic inputs test calculations, not investment conclusions. Offer the first real company investigation following the bundled investing skill, preserving evidence gaps. Read preferences before choosing horizon, research focus or output currency. Never change a model's currency label without converting its values explicitly.
7. If daily monitoring was requested, use the host's supported scheduler with `schedule-prompt`, the user's time and timezone. If unavailable, provide the prompt and mark scheduling pending. Do not install cron or claim an automation exists just because a time was saved. A first actual scheduled execution must be observed before marking it verified. Notify for material developments, failures or required action; no-change stays quiet.
8. Write an ignored `private/setup-summary.md`: installation result, live X result and timestamp, confirmed vs unresolved watchlist, local preference paths, model smoke result, portfolio/sizing readiness, schedule state, and outstanding actions. Link the user's first dossier when available. Say precisely what is ready and what is pending; do not label the entire setup complete while required checks are outstanding.
